The question

How should T3 Code use aigate (deployed on .10, https://aigate.shoemoney.ai) for authentication and model listing — selecting among Claude setup-token accounts with the most headroom, hopping when one runs dry (as the shell warden aigate-run.sh does), and surfacing alt-endpoint models like Muse — as a first-class T3 Code feature?

Verdict — VERIFIED-backed consensus (converged in substance)

Opt-in generic credential broker, Claude-only v1, resolved at session start through the existing per-instance env seam under per-instance CLAUDE_CONFIG_DIR isolation. No Keychain manipulation. Account hop is Phase 2, turn-boundary only, via kill-query → re-select → recreate-with-resume-cursor. Muse/Kimi are T3-side route profiles (env overlays + per-instance additional models), never an aigate endpoint. Codex/Cursor/Grok/OpenCode explicitly unsupported. Fork-first; one small generic hook is the sole upstream candidate. Full implementation plan: plan.md beside this file.

Chair ruling note: round-2 seats voted ready=1, not-ready=4 — but every not-ready condition named the same items (no Keychain deletion, no CredentialBroker cathedral, no aigate models endpoint, cross-account resume proven). The chair ran the deciding experiment (EXP-8, passed) and rules the conditions honored. Recorded per the "conditions-as-verdict" pattern.
